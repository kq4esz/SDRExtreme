# Signal Outpost 0.12.0

## MeshCore repeaters heard and incoming hops

- Show the count of distinct local repeater IDs heard rebroadcasting a channel
  message, separately from the number of matching radio copies.
- Match the complete encrypted message payload, independent of its changing
  flood path, rather than associating unrelated nearby radio activity.
- Add known repeater names, short hashes, ambiguous/unknown identity labels,
  per-repeater repeat counts, last-heard time and SNR/RSSI to **Receipt & path**.
- Add expandable observed rebroadcast paths. The final path hash is the nearby
  rebroadcaster; upstream relay IDs are not all counted as local repeaters.
- Show received-message relay hop counts on channel and direct-chat messages.
  Decode the packed hash width/count field correctly. Routed messages whose
  firmware supplies no measured count show **Hops not reported**.
- Add received-message details and, when available, a matching observed channel
  copy's path. Preserve existing saved hop metadata for older messages.
- Keep channel keys in host memory only. Save compact observation metadata with
  chat history, and coalesce radio updates to reduce UI/storage churn.

Channel messages still stop after the first accepted broadcast and retry only
explicit local-node send errors. Hearing a rebroadcast is not a delivery/read
receipt from channel members. Short relay IDs can collide; unknown names and
unreported hop counts are not guessed. Historical messages without observations
remain marked as unrecorded.

Use **Help → Check for updates**, then restart to install. No live radio message
is transmitted during the build/package checks. The Windows installer remains
unsigned.
