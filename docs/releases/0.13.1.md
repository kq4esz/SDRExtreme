# Signal Outpost 0.13.1

## Flood advertisements from a logged-in MeshCore repeater

- Add **Advert Flood from Repeater** beside **Refresh status** in the repeater
  login panel. It appears after confirmed login and requires administrator
  access; legacy firmware enforces permissions when it omits the access flag.
- Send the repeater's `advert` CLI command through the connected companion over
  LoRa, using the selected repeater's configured identity and flood scope.
- Keep command drafts intact and display the repeater's reply in its console.
  Confirm the request only on the expected `OK - Advert sent` reply. A local
  companion send acknowledgement does not establish repeater execution or
  reception by other nodes.
- Disable the button while a repeater operation is pending, reject stale
  connection requests, and do not automatically retry or advertise on login.
- Require CLI replies for remote commands and use distinct command timestamps
  so separate clicks are not mistaken for retries by repeater firmware.

Use **Help → Check for updates**, then restart to install. The Windows installer
remains unsigned. Build/package checks do not transmit advertisements; live
repeater radio operation has not been exercised.
